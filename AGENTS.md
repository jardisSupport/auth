# jardissupport/auth

Authentication, session management, password hashing, and RBAC — no HTTP layer, no JWT, no framework coupling. Eight Orchestrators following the Closure-Orchestrator Pattern: `SessionManager`, `PasswordAuthenticator`, `TokenAuthenticator`, `TokenIssuer`, `TokenRedeemer`, `DbTokenStore`, `PasswordHasher`, `Guard`.

## Usage essentials

- **Strict Orchestrator Pattern:** Eight Orchestrators in `src/` root compose themselves from Closures (`src/Handler/{Category}/`) via `->__invoke(...)` binding in the constructor. Orchestrators have **zero business logic** — only delegation.
- **Events are plain readonly data objects** under `src/Data/Event/` (`AuthenticationSucceeded/Failed`, `SessionCreated/Refreshed/Invalidated`, `AllSessionsInvalidated`) — no interface, no Dispatcher. `SessionManager::create()/refresh()` return `SessionResult` with events; `invalidate()/invalidateByReference()/invalidateAll()` return the event directly (`invalidateByReference($ref)` revokes exactly one session incl. its paired refresh token via the internal claims `_refresh`/`_access`, idempotent; `_`-claims never reach `Session::metadata`). The caller dispatches itself.
- **`DbTokenStore($connection, $table = 'auth_tokens')`** implements `TokenStoreInterface` via `jardissupport/dbquery` on a `DbConnectionInterface` (hash only; DDL per dialect in `resources/sql/{mysql,pgsql,sqlite}.sql`). **`TokenAuthenticator($store, $verifyToken, $tenantClaim = SessionClaim::TENANT, $expectedType = TokenType::Access)`** turns `Credential::token($plain)` into a `TenantAuthResult` (`SessionAwareAuthResultInterface`: `getSubject()` `user:42`, `getSubjectId()` `42`, tenant from the access-token claim, `getSessionReference()` = `HashedToken::hashOf($plain)` — the one token-hash function, also used by `VerifyToken`/`RefreshSession`; reasons `Invalid token`/`Token expired`/`Token revoked`/`Unsupported credential type`). Attribute names for transports: `RequestAttribute::SUBJECT|SUBJECT_ID|TENANT|SESSION` (contracts >= 2.9). The test fake `InMemoryTokenStore` lives in `tests/Support/`; tests run against MariaDB 11.8 (`make phpunit` starts it). `PasswordHasher::argon2id(memoryCost, timeCost, threads)` or `::bcrypt(cost)` as Factory Named Constructors.
- **`PasswordAuthenticator($hasher, $sessions, Closure|UserLookupInterface $userLookup)`** (hasher: `PasswordHasherInterface`); with the interface (contracts >= 2.10) `Handler/Authentication/LookupCredentialRecord` maps `CredentialRecordInterface` to the closure array (`Subject::parse`, claims passed through). **`TokenIssuer($store, $tokenLength = 32)->issue(TokenType, Subject, $ttl, $claims = []): IssuedToken{plain, hashed}`** and **`TokenRedeemer($store, $verifyToken)->redeem($plain, TokenType): HashedTokenInterface`** (one-time: revokes on success; unknown/wrong type `InvalidCredentialException`, expired `TokenExpiredException`, second call `TokenRevokedException`).
- **`Guard` against immutable `Policy` via `PolicyBuilder`:** `role()->allow()->deny()->includes()->build()`. Rule semantics: **deny overrides allow**, role inheritance via `includes('editor')`. `check()` returns bool, `authorize()` throws `UnauthorizedException` (extends `RuntimeException`, **not** `AuthenticationException`).
- **Multi-role support:** `$session->getMetadata()[SessionClaim::ROLE]` may be `string` or `string[]` — `CheckPermission` iterates the list, **first match wins**. Permission format `"resource:action"` via `Permission::from()` with wildcard support.
- **Public error messages stay generic** (`"Invalid credentials"`), details are only in the events. `AuthenticationResult` implements `AuthResultInterface` — usable as both rich result and contract type. Exception hierarchy: `AuthenticationException` (base) → `InvalidCredential`/`TokenExpired`/`TokenRevoked`; `UnauthorizedException` separate.
