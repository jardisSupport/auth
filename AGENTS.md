# jardissupport/auth

Authentication, session management, password hashing, and RBAC — no HTTP layer, no JWT, no framework coupling. Ten Orchestrators following the Closure-Orchestrator Pattern: `SessionManager`, `PasswordAuthenticator`, `SignedTokenAuthenticator`, `TokenAuthenticator`, `TokenIssuer`, `TokenRedeemer`, `DbTokenStore`, `PasswordHasher`, `Guard`, `AuthServices` (a plain bundle; `AuthServices::fromStore($store, $key, ?$hasher)`).

## Usage essentials

- **Strict Orchestrator Pattern:** Eight Orchestrators in `src/` root compose themselves from Closures (`src/Handler/{Category}/`) via `->__invoke(...)` binding in the constructor. Orchestrators have **zero business logic** — only delegation.
- **Events are plain readonly data objects** under `src/Data/Event/` (`AuthenticationSucceeded/Failed`, `SessionCreated/Refreshed/Invalidated`, `AllSessionsInvalidated`) — no interface, no Dispatcher. `SessionManager::create()/refresh()` return `SessionResult` with events; `invalidate()` returns its event directly; `invalidateByReference()/invalidateAll()` return `void` since v1.6 (`SessionManagerInterface` of contracts 2.11; the handlers still return the events) (`invalidateByReference($sid)` revokes exactly one session's refresh token, idempotent; `_`-claims never reach `Session::metadata`). The caller dispatches itself.
- **Session tokens (v1.5, Bescheid N10):** `new SessionManager($store, #[\SensitiveParameter] string $accessTokenKey, ...)` — key is **required**, raw **32 bytes** (`.env` `AUTH_TOKEN_KEY` is base64, the caller decodes; other length = `InvalidArgumentException`). Access token = `base64url(json{typ:"access",sub,sid,iat,exp,claims}) . '.' . base64url(sodium_crypto_auth mac)` (`Handler/Token/SignAccessToken` / `VerifyAccessToken`), **never stored**, verified by `SignedTokenAuthenticator($key, $tenantClaim, ?Closure $clock)` without any store/DB access (reasons `Invalid token`/`Token expired`/`Unsupported credential type`). `sid` = SHA-256 hash of the session's refresh token = `getSessionReference()` = `Session::tokenHash`. Refresh token stays opaque in `TokenStoreInterface`. Revocation (`invalidate*`) acts on the refresh token — an issued access token lives until `exp` (default 900 s, refresh 604800 s). Key rotation invalidates all access tokens. `TokenAuthenticator` remains for stored tokens (`ApiKey`/`Verification`/`PasswordReset`, `TokenIssuer`-issued).
- **`DbTokenStore($connection, $table = 'auth_tokens')`** implements `TokenStoreInterface` via `jardissupport/dbquery` on a `DbConnectionInterface` (hash only; DDL per dialect in `resources/sql/{mysql,pgsql,sqlite}.sql`). **`TokenAuthenticator($store, $verifyToken, $tenantClaim = SessionClaim::TENANT, $expectedType = TokenType::Access)`** turns `Credential::token($plain)` into a `TenantAuthResult` (`SessionAwareAuthResultInterface`: `getSubject()` `user:42`, `getSubjectId()` `42`, tenant from the access-token claim, `getSessionReference()` = `HashedToken::hashOf($plain)` — the one token-hash function, also used by `VerifyToken`/`RefreshSession`; reasons `Invalid token`/`Token expired`/`Token revoked`/`Unsupported credential type`). Attribute names for transports: `RequestAttribute::SUBJECT|SUBJECT_ID|TENANT|SESSION` (contracts >= 2.9). The test fake `InMemoryTokenStore` lives in `tests/Support/`; tests run against MariaDB 11.8 (`make phpunit` starts it). `PasswordHasher::argon2id(memoryCost, timeCost, threads)` or `::bcrypt(cost)` as Factory Named Constructors.
- **`PasswordAuthenticator($hasher, $sessions, Closure|UserLookupInterface $userLookup)`** (hasher: `PasswordHasherInterface`); with the interface (contracts >= 2.10) `Handler/Authentication/LookupCredentialRecord` maps `CredentialRecordInterface` to the closure array (`Subject::parse`, claims passed through). **`TokenIssuer($store, $tokenLength = 32)->issue(TokenType, Subject|string, $ttl, $claims = []): IssuedToken{plain, hashed}`** and **`TokenRedeemer($store, $verifyToken)->peek|redeem($plain, TokenType): HashedTokenInterface`** (`peek` = `Handler/Token/PeekToken`: same checks, no revoke) (one-time: revokes on success; unknown/wrong type `InvalidCredentialException`, expired `TokenExpiredException`, second call `TokenRevokedException`).
- **`Guard` against immutable `Policy` via `PolicyBuilder`:** `role()->allow()->deny()->includes()->build()`. Rule semantics: **deny overrides allow**, role inheritance via `includes('editor')`. `check()` returns bool, `authorize()` throws `UnauthorizedException` (extends `RuntimeException`, **not** `AuthenticationException`).
- **Multi-role support:** `$session->getMetadata()[SessionClaim::ROLE]` may be `string` or `string[]` — `CheckPermission` iterates the list, **first match wins**. Permission format `"resource:action"` via `Permission::from()` with wildcard support.
- **Public error messages stay generic** (`"Invalid credentials"`), details are only in the events. `AuthenticationResult` implements `AuthResultInterface` — usable as both rich result and contract type. Since v1.7 (contracts >= 2.12) `Data\Session` also implements `SessionInterface::getExpiresAt(): ?DateTimeImmutable` (returns the unchanged public `expiresAt`). Since v1.6 (contracts >= 2.11) `SessionManager`, `TokenIssuer`, `TokenRedeemer`, `SessionResult`, `IssuedToken`, `TenantAuthResult` (`getRole()` from claim `SessionClaim::ROLE`, `RoleAwareAuthResultInterface`) implement the `Contract\Auth` interfaces; subjects are accepted as `type:id` strings (and still as `Subject`). Exception hierarchy: `AuthenticationException` (base) → `InvalidCredential`/`TokenExpired`/`TokenRevoked`; `UnauthorizedException` separate.
